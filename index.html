how it works

Three moves. No middleman.

Every step below is a real function in CertificateRegistry.sol, not a diagram of one.

1

University issues

A whitelisted wallet calls issueCertificate(). The contract rejects empty fields and duplicate IDs, stores the record, and emits an event. MetaMask pops up, you pay a little gas, and the cert is on-chain.

2

Student flexes

Open the Student page, search the ID, and print a certificate with a QR code. Save it as PDF from the browser. Students only ever read; they can't issue or revoke anything.

3

Employer checks

The Verify page talks straight to the contract with verifyCertificate(). No wallet, no account. You get VERIFIED, REVOKED, or NOT FOUND, plus who issued it and the transaction.

what's on-chain

The whole record, in one struct.

This is exactly what gets stored for each certificate. Yes, it's all public. More on that below.

CertificateRegistry.sol
struct Certificate {
  string  certificateId;
  string  studentName;
  string  registrationNumber;
  string  courseName;
  string  universityName;
  string  grade;
  string  issueDate;
  address issuerAddress;
  bool    isRevoked;
  bool    exists;
}

about

Read this before you put real names in.

Heads up: anything stored on a public blockchain is readable by everyone and can never be deleted. This project stores names and grades on-chain because it's a classroom demo. Use fake data. A real system would keep the details in a private database and put only a hash of them on-chain, so the proof stays public and the personal data doesn't. The project report explains the design.
